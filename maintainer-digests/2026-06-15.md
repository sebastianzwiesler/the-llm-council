## Step 3 — Gate Decision

**Threshold = 8** (documented default; placeholder never substituted). **Result: GATE FAILED — build nothing.**

The top candidate clears the numeric bar (40.0 ≥ 8) and carries no multi-run flag, but **fails criterion 3** — "a self-contained change you can complete cleanly in one run" — verified read-only against source:

- **`budget_class` is plumbed but not used for selection.** It is computed and stored in the capability plan and surfaced into prompts/metadata (`engine/orchestrator.py:1367`, `:1842`), but model selection (`:1297–1305`) resolves `_resolved_model_pack` purely from `config.model_pack` or `get_model_pack(subagent_config, mode)`. No branch consults `budget_class`. The scout's claim is accurate.
- **Two parallel selection axes must be reconciled.** `model_pack` (FAST/REASONING/CODE…) is *already* the model-selection mechanism; `budget_class` (cheap/normal/premium) is a second axis. Deciding whether budget_class overrides, maps onto, or is subordinate to model_pack is a design decision, not a mechanical patch — directly contradicting the Effort=2 score.
- **Escalation restructures a central, sensitive loop.** The synthesis-retry loop (`:926–1049`) re-runs with the *same* model pack. "Escalate to a stronger model on validation failure" means swapping models mid-loop — a behavioral change to the core flow.
- **No verification safety net exists.** Only `evals/runtime-baseline.yaml` exists; the per-mode baselines (candidate #2) do not. There is no way to prove cheaper models don't regress output quality across modes — so the change cannot be *verified* clean in one run, which the project's "evidence before assertions" bar requires.
- **High blast radius:** changes which model *every* run uses (router/synthesizer → cheap, planner/arch → premium) for all users.

This is materially the same class of deep-orchestrator change that Run 2 (2026-06-08) correctly gated out. Building it now would ship an unverifiable default-behavior change.

### One-paragraph implementation plan for the top item (for a future, scoped effort)

Treat this as a deliberate, sequenced feature, not a one-run patch — and **build candidate #2 (per-mode eval baselines) first** so the routing change has a regression net. (1) **Define the mapping:** decide budget_class ↔ model_pack semantics explicitly — e.g. budget_class selects a model_pack *tier* only when the caller has not pinned `model_pack`/`--models`, never weakening an explicit override (mirror the existing "overrides strengthen, never weaken" rule in `capabilities._apply_capability_overrides`). (2) **Wire selection:** in `orchestrator.py:1297–1305`, when no explicit pack is set, resolve the pack from `self._capability_plan.budget_class` (cheap→FAST, normal→subagent default, premium→REASONING/CODE_COMPLEX) and record the source in `execution_plan` for observability. (3) **Add escalation:** in the synthesis-retry loop (`:926–1049`), on schema-validation failure, re-resolve to a stronger pack for the next attempt (premium tier), bounded by `max_retries`, and log the escalation. (4) **Prove no regression:** run the new per-mode eval baselines before/after, asserting equal-or-better validation pass-rate and a measured cost delta; add unit tests with a mocked provider asserting the cheap→premium escalation path fires only on validation failure. (5) Ship behind a config flag (`enable_adaptive_routing`, default off) for one release before making it default.
